### ✨ Feature Request — Real Elo Rating System with AI Difficulty Mapping

### 📋 Problem Statement

The current rating system in `game/rating_service.py` uses a **flat, fixed point system** that is not meaningful or fair:

```python
def calculate_rating_change(result):
    if result == "win":   return +20
    if result == "draw":  return +5
    if result == "loss":  return -10
```

This means:
- A **1200-rated** player beating an **800-rated** opponent gains the same `+20` as beating a **2000-rated** opponent.
- Ratings **inflate over time** (wins always give +20, losses only −10) and do not converge to a player's true skill level.
- In PvE (AI) mode, there is **no opponent rating** at all — every AI win/loss applies the same static delta regardless of difficulty.

The result is a rating number that has no statistical meaning and fails to motivate players.

### 💡 Proposed Solution

Implement the **Elo rating formula** as used in standard chess:

```
Expected Score  = 1 / (1 + 10 ^ ((opponent_rating - player_rating) / 400))
Rating Change   = K × (actual_score - expected_score)
```

Where:
- `actual_score` = 1 (win), 0.5 (draw), 0 (loss)
- `K` = K-factor (suggested: **32** for all players to keep it responsive)

#### AI Difficulty → Opponent Rating Mapping

| Difficulty | AI "Rating" |
|------------|-------------|
| Easy       | 800         |
| Medium     | 1200        |
| Hard       | 1600        |

#### Example Calculations

| Player Rating | AI Difficulty | Result | Δ Rating |
|---------------|---------------|--------|----------|
| 1200          | Easy (800)    | Win    | +7       |
| 1200          | Easy (800)    | Loss   | −25      |
| 1200          | Medium (1200) | Win    | +16      |
| 1200          | Hard (1600)   | Win    | +25      |
| 1200          | Hard (1600)   | Loss   | −7       |

This makes a win against **Hard AI much more rewarding** and a loss against **Easy AI much more penalizing**.

### 🗂️ Files to Modify

- `game/rating_service.py` — Replace `calculate_rating_change(result)` with
  `calculate_rating_change(result, player_rating, opponent_rating, k=32)`
- `game/views.py` — Update all callers of `update_player_rating()` to pass
  `opponent_rating` (derived from AI difficulty in PvE, or opponent's actual rating in PvP)
- `game/views.py` → `update_player_rating()` — Accept and forward `opponent_rating`
- `game/views.py` → `ai_move()`, `make_move()`, `resign_game()`, `offer_draw()` — Resolve AI opponent rating from `request.session.get('difficulty')`

### 🔧 Implementation Direction

**Step 1 — Update `rating_service.py`:**
```python
def calculate_rating_change(result, player_rating, opponent_rating, k=32):
    """Compute Elo rating change."""
    score = {"win": 1.0, "draw": 0.5, "loss": 0.0}[result]
    expected = 1 / (1 + 10 ** ((opponent_rating - player_rating) / 400))
    change = round(k * (score - expected))
    return change
```

**Step 2 — Resolve opponent rating in `update_player_rating()`:**
```python
AI_RATINGS = {"easy": 800, "medium": 1200, "hard": 1600}

def update_player_rating(user, winner, player_color, mode="pvp", difficulty="medium"):
    rating, _ = PlayerRating.objects.get_or_create(user=user)
    opponent_rating = AI_RATINGS.get(difficulty, 1200) if mode == "ai" else 1200
    result = "win" if winner == player_color else ("draw" if winner == "draw" else "loss")
    change = calculate_rating_change(result, rating.rating, opponent_rating)
    ...
```

**Step 3 — Pass difficulty from session into callers:**
```python
# In views.py wherever update_player_rating is called:
difficulty = request.session.get("difficulty", "medium")
update_player_rating(user, winner, player_color, mode=game.mode, difficulty=difficulty)
```

- Does this break existing ratings? **Yes** — existing stored ratings were computed with the flat system and will be inconsistent after this change. Consider a one-time migration to reset all ratings to `1200` (the standard Elo starting point) when this is merged.
- Related models: `game/models.py` → `PlayerRating`, `RatingHistory` — no schema changes needed.
- The `RatingHistory` model already stores `old_rating`, `new_rating`, and `rating_change` — it will automatically reflect the new Elo deltas.
- Workarounds (if any): None — the flat system must be replaced entirely for ratings to be meaningful.
